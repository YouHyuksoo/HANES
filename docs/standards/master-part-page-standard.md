# 품목마스터 페이지 표준

## 목적

`/master/part` 화면을 기준으로, HANES 기준정보 유지보수 화면의 레이아웃과 컨트롤 배치 원칙을 추출한다.
이 문서는 특정 화면을 그대로 고정하는 문서가 아니라, 품목마스터 화면에서 확인된 패턴을 표준으로 정리한 문서다.

## 기준 화면

- URL: `/master/part`
- 역할: 기준정보 > 품목관리
- 화면 성격: 좌측 목록 + 우측 슬라이드 패널 조합의 마스터 관리 화면

## 화면 구조

1. 최상단 전역 헤더에는 검색, 테마, 언어, 도움말, 회사/사업장 표시, 사용자 메뉴가 있다.
2. 본문 상단에는 브레드크럼 탭처럼 `대시보드 > 품목관리`가 보인다.
3. 페이지 헤더는 제목과 설명을 왼쪽에 두고, 주요 액션을 오른쪽에 둔다.
4. 본문은 좌측 그리드와 우측 생성/수정 패널로 나뉜다.
5. 우측 패널이 열려도 좌측 목록 구조는 유지된다.

## 상단 액션 규칙

1. `ERP 동기화`, `새로고침`, `품목 추가`는 제목 오른쪽 한 줄에 배치한다.
2. 이 순서는 고정한다.
3. `ERP 동기화`와 `새로고침`은 중립형 outline 버튼으로 둔다.
4. `품목 추가`는 primary 버튼으로 강조하고, 화면의 대표 생성 동작으로 사용한다.
5. 상단 버튼 높이는 36px 계열로 맞춘다.
6. 아이콘은 버튼 안에서 텍스트 앞에 배치한다.
7. 우측 하단의 파란 `+` 플로팅 버튼이 있더라도, 상단 `품목 추가`가 공식 진입점이다.

## 목록 영역 규칙

1. 검색창이 필터 줄의 첫 요소다.
2. 그 뒤에 유형, 사용여부 같은 선택 필터를 둔다.
3. 우측 끝에는 그리드 옵션과 전체화면 같은 아이콘 버튼을 둔다.
4. 표는 좁게 압축된 운영용 밀도와 긴 컬럼 폭을 동시에 지원해야 한다.
5. 첫 번째 컬럼은 `수정/삭제` 같은 행 단위 관리 액션 전용으로 둔다.
6. 사진 컬럼은 실제 이미지가 없으면 자리표시 아이콘을 보여준다.
7. 컬럼 헤더에는 고정, 정렬, 너비 조절을 위한 보조 아이콘이 붙는다.
8. 헤더는 길어질 수 있으므로 줄바꿈보다 폭 조절과 고정 우선으로 다룬다.

## 배지 규칙

1. 분류값, 상태값, 유형값은 텍스트만 노출하지 말고 배지로 표시한다.
2. 배지는 12px 폰트 크기의 작은 pill 형태를 사용한다.
3. 배지는 2px 8px 계열의 얇은 패딩과 작은 반경을 가진다.
4. 배지 색은 상태를 구분하는 보조 정보로만 쓰고, 본문 텍스트를 대체하지 않는다.
5. 배지 문구는 짧게 유지한다. 예: `원자재`, `반제품`, `완제품`.

## 우측 패널 규칙

1. 생성/수정은 모달보다 우측 슬라이드 패널을 우선한다.
2. 패널 제목은 `품목 추가`처럼 동작을 바로 알 수 있어야 한다.
3. 패널 헤더 우측에는 `취소`와 primary `추가/저장` 버튼을 둔다.
4. 패널은 스크롤 가능한 폼 본문을 가진다.
5. 패널이 열려도 목록은 배경 컨텍스트로 남겨둔다.
6. 필수 항목은 라벨 옆 빨간 `*`로 표시한다.
7. 라벨 옆 정보 아이콘은 도움말이 아니라 필드 의미와 DB 컬럼 출처를 설명해야 한다.
8. 입력 순서는 기본정보, 수량/보관, 사진, 비고로 읽히게 유지한다.

## 폼 배치 규칙

1. 기본정보는 2열 그리드를 기본으로 한다.
2. 코드성 값은 자유입력보다 선택형을 우선한다.
3. 텍스트 설명형 값은 짧은 단일 행 입력을 쓴다.
4. 숫자 값은 숫자 입력으로 처리한다.
5. `사용여부`는 라디오처럼 즉시 상태를 보여주는 형태가 적합하다.
6. `품목고정 적재로케이션`처럼 후보가 명확한 값은 선택형으로 둔다.
7. 이미지 업로드는 별도 버튼/드롭존으로 분리한다.

## 색상과 타이포 규칙

1. 주요 강조색은 진한 마젠타다.
2. 채워진 primary 버튼과 생성 버튼은 같은 계열의 강한 색을 쓴다.
3. 보조 버튼은 흰 배경과 얇은 경계선의 중립 톤을 쓴다.
4. 텍스트 버튼과 필드 라벨은 14px 계열을 기준으로 한다.
5. 배지는 12px 계열을 기준으로 한다.
6. 카드, 버튼, 입력의 반경은 과하게 크지 않게 8px 수준으로 유지한다.

## 유지보수 규칙

1. 이 화면에서 확인된 상단 액션 위치와 버튼 계층을 표준 우선순위로 삼되, 기능 변경이 생기면 문서를 먼저 갱신한다.
2. 목록과 우측 패널의 분할 구조는 기본 패턴으로 유지하되, 동일한 유지보수 목적을 더 잘 만족하는 대안이 있으면 그 대안을 문서화한다.
3. 행 액션은 아이콘 중심으로 유지하고 텍스트 버튼으로 바꾸지 않는다.
4. 필드 라벨의 DB 컬럼 설명은 실제 스키마와 맞춰 갱신한다.
5. 새 컬럼을 추가할 때는 이 문서의 폼 배치 규칙과 함께 갱신한다.
6. 목록에 새 상태/분류를 추가하면 배지 규칙도 함께 검토한다.

## 품목 필드 변경 영향 파일 맵

품목 필드를 추가, 삭제, 이름 변경, 필수화할 때는 아래 순서로 확인한다.

1. DB 컬럼 매핑: `apps/backend/src/entities/item-master.entity.ts`
2. API 입력/조회 규칙: `apps/backend/src/modules/master/dto/part.dto.ts`
3. 저장/수정 매핑과 기본값: `apps/backend/src/modules/master/services/part.service.ts`
4. 프론트 행 타입: `apps/frontend/src/app/(authenticated)/master/part/types.ts`
5. 입력 폼: `apps/frontend/src/app/(authenticated)/master/part/components/PartFormPanel.tsx`
6. 목록 컬럼명과 셀 표시 방식: `apps/frontend/src/app/(authenticated)/master/part/partColumns.tsx`
7. 목록 조회와 서버 필터 파라미터: `apps/frontend/src/app/(authenticated)/master/part/page.tsx`
8. 라벨/도움말: `apps/frontend/src/locales/ko.json`
9. 회귀 테스트: `apps/frontend/src/app/(authenticated)/master/part/*.structure.test.mjs`, `apps/backend/src/modules/master/services/part.service.spec.ts`

코드성 값은 자유입력으로 추가하지 말고 공통코드 또는 기준정보 선택 컴포넌트부터 확인한다.

## 품목 검사 규칙 변경 영향 파일 맵

IQC 대상, 검사구분, AQL 정책 필수 여부 같은 검사 규칙은 `packages/shared/src/utils/part-rules.ts`를 먼저 변경한다.

그 다음 아래 호출부가 같은 의미로 동작하는지 확인한다.

1. 프론트 저장 가능 조건: `apps/frontend/src/app/(authenticated)/master/part/components/PartFormPanel.tsx`
2. 과거 모달 호출부: `apps/frontend/src/app/(authenticated)/master/part/components/PartFormModal.tsx`
3. 백엔드 저장 차단 규칙: `apps/backend/src/modules/master/services/part.service.ts`
4. 구조 테스트: `apps/frontend/src/app/(authenticated)/master/part/part-iqc-aql-guard.structure.test.mjs`
5. 백엔드 단위 테스트: `apps/backend/src/modules/master/services/part.service.spec.ts`

## 좋은 예시

- 기준정보 화면에서 제목과 주요 생성 액션을 한 줄에 묶고, 목록과 생성 패널을 분리하는 방식
- 상태값을 12px 배지로 압축해 표시하고, 상세 설명은 툴팁으로 분리하는 방식
- 라벨 도움말에 DB 컬럼 출처를 함께 적어 유지보수자가 의미를 바로 추적할 수 있게 하는 방식

## 나쁜 예시

- 생성/수정 폼을 중앙 모달로 바꿔 목록 맥락을 끊는 방식
- 상단 주요 액션을 여러 줄로 흩어 놓는 방식
- 상태값을 색상만으로 표현하고 텍스트 표식을 제거하는 방식
- 자유입력으로 코드성 값을 받는 방식

## 적용 체크리스트

1. 상단 주요 액션이 `ERP 동기화`, `새로고침`, `품목 추가` 순서로 보이는가
2. 목록이 검색/필터/그리드의 운영용 밀도를 유지하는가
3. 배지가 12px 계열의 compact pill 형태인가
4. 우측 패널이 슬라이드 방식으로 열리고 헤더 액션이 분리돼 있는가
5. 필수 필드와 DB 컬럼 출처가 라벨에서 바로 확인되는가
6. 신규 필드가 추가될 때 이 문서가 같이 갱신되는가

## 비고

- 이 문서는 현재 구현을 참고해 정리한 운영 표준이다.
- 레이아웃이나 배치가 바뀌면 이 문서를 먼저 갱신하고 코드에 반영한다.
