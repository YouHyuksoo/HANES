## 완료한 것

- FG 라벨에는 별도 생산 LOT 키가 없음을 entity와 JSHANES 스키마에서 확인했다. 작업지시 전체를 자동 판정하지 않고, 작업지시 안의 통전합격·육안대기 FG를 작업자가 이번 LOT 대상으로 선택해 한 번에 판정하도록 구현했다.
- `GET /quality/continuity-inspect/visual-pending/:orderNo`는 같은 tenant·작업지시의 `ISSUED`, `INSPECT_PASS_YN=Y`, 최신 `CONTINUITY=Y` FG만 반환한다.
- `POST /quality/continuity-inspect/visual-inspect-batch`는 작업지시와 1~100개 FG를 필수로 받고, 정렬된 FG 행 잠금 후 전부 검증한 다음 한 트랜잭션으로 판정한다. 각 FG마다 `INSPECT_RESULTS`가 남아 시리얼 추적성을 보존한다.
- 일괄 경로는 `ISSUED` 및 작업지시 일치를 강제한다. 단건 재판정 호환은 유지하되 `PACKED/SHIPPED/VOIDED` 상태 역전은 모든 경로에서 차단한다.
- 화면은 대기목록, 개별/전체 선택, 선택 건수, 최대100건 제한을 제공한다. 작업지시 변경 중 이전 조회 응답이 history/pending/error를 덮지 않도록 현재 작업지시 guard를 적용했다.
- 회로라벨 입력값은 앞뒤 공백을 제거하고 기존 tenant 범위 중복 차단을 유지한다. 화면 안내는 시스템이 실제 보장하는 “현장 회로라벨 스캔·사용 라벨 중복 거부”로 명확히 했다.
