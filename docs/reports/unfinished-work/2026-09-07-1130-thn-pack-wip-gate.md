# THN 포장 공정창고 대상 기준 적용

- 일시: 2026-09-07
- 작업: `T-THN-PACK-WIP-GATE`
- 상태: 구현·로컬 검증 완료, 커밋·배포 전

## 확정한 업무 기준

포장은 생산 공정에서 수행한다. 포장 대상은 별도 부서가 아니라 공정창고 `FG_WIP`에 생산입고되어 아직 제품입고되지 않은 외관합격 완제품이다. 포장 이후 제품입고에서 완제품 창고재고로 이동한다.

## 변경

- 포장대기 조회를 `FG_LABELS`의 상태만 보던 방식에서 조립실적과 완료된 `ASSEMBLY/WIP_IN → FG_WIP` 원장까지 확인하도록 강화했다.
- 박스 추가와 박스 마감에서도 같은 조건을 재검증한다.
- 조립실적·공정입고 이력이 없는 외관합격 seed 라벨은 포장 대상에서 제외한다.
- 현재 재고 테이블은 품목 단위 집계이고 시리얼별 위치를 저장하지 않는다. 정상 업무 흐름에서는 `VISUAL_PASS` 상태와 조립 `FG_WIP` 입고 이력을 함께 현재 포장대기품의 근거로 사용한다. 임의 재고조정까지 시리얼 단위로 판별하려면 별도 시리얼 위치 원장이 필요하다.

## 검증

- `box.service.spec.ts`: 포장대기 조회, 박스 추가 차단, 마감 재검증 포함.
- JSHANES 실제 데이터 `FG26090600418`: 외관합격 처리 후 포장대기 조회와 임시 박스 추가 성공, 전체 트랜잭션 롤백 성공.
- 사후 확인: 임시 박스 `BX-ROLLBACK-FGWIP` 0건, FG 상태 `ISSUED` 복원.
- 실제 API 포장대기 조회에서 원장 없는 seed 6건이 제외되어 0건 반환.

## 남은 작업

- 수정 커밋과 배포 SHA가 없으므로 개선요청 상태는 `IN_PROGRESS`로 유지해야 한다.
- 테스트용 업무 데이터는 남기지 않았다.
