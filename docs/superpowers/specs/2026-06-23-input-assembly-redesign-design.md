# 조립공정 실적입력(input-assembly) 재설계

- 작성일: 2026-06-23
- 대상: `/production/input-assembly` (실적입력-조립) + 설비 자재 장착 기반
- 범위: **(A) 단계** — ① 설비 자재 장착(WIP_MAT_STOCKS 단일 출처) ② 조립 화면 재구성. 키오스크 자재 모델 전환은 별도 후속 단계.

## 1. 문제 / 목적

현재 화면은 `작업지시 → BOM요구사항 → SG스캔 → 실행` 카드가 세로로 길게 쌓여 공간을 낭비하고, 스캔 영역이 고정되지 않아 사용성이 떨어진다. 또한 추적성 구조가 의도와 다르다.

**핵심 목적**: 최초 조립공정에서 이전 공정 바코드를 가진 **회로반제품(SG)** 과 **설비에 장착된 자재**를 조합해 실적을 만들고, **최종 제품 라벨(FG) 1장을 출력 → 그 실물 라벨을 스캔하는 순간** 투입된 반제품·자재로 매핑되어 추적성이 확정되는 구조.

## 2. 핵심 모델 (grill로 확정)

### 2.1 투입물 2종 — 생명주기가 다름
| 투입물 | 출처 | 채우는 방식 | 리셋 |
|--------|------|-----------|------|
| **반제품(회로)** | `SG_LABELS` | 제품 1개분 세트 스캔 | 실물 라벨 스캔 후 **리셋** |
| **자재(LOT)** | `WIP_MAT_STOCKS` (설비 장착) | 설비에 스캔 투입, 떨어지면 보충 | 명시적 해제(반품) 전까지 **유지** |

### 2.2 자재 = 설비 단위 장착 (작업지시 무관)
- 자재는 **설비(EQUIP_CODE)** 에 투입(장착)되며, 작업지시는 참조일 뿐. 한번 설비에 장착되면 어떤 작업지시에서든 사용·차감된다.
- 단일 출처: `WIP_MAT_STOCKS` (복합PK: company, plant, equipCode, itemCode, matUid / QTY·AVAILABLE_QTY). 이미 설비 단위 공정재고로 존재.
- DB 저장 → 화면 껐다 켜도 복원. 명시적 해제(반품) 전까지 유지.

### 2.3 커밋(확정) 시점 — 2단계 분리
| 단계 | 동작 | DB 반영 |
|------|------|---------|
| ① 반제품 스캔 / 자재 장착 | 반제품=화면 임시 목록(리셋 가능) · 자재=설비에 장착(WIP_MAT_STOCKS DB) | 자재 장착만 DB |
| ② 조립 실행 | **FG 바코드 1개 채번 + 제품 라벨 1장 출력** | FG 바코드만(`ISSUED`, 매핑·소비·실적·재고 미반영) |
| ③ 실물 FG 라벨 스캔 | **추적성 확정** | `genealogy(FG→SG, FG→MAT_LOT)` + SG 잔량 소비 + 설비 WIP 자재 BOM 차감 + `ProdResult` + FG WIP 재고 — **단일 트랜잭션** |

- 매핑/추적성은 **③ 실물 라벨 스캔 시점에만** 생성된다(SG는 그전까지 리셋 가능한 준비 데이터). 라벨이 훼손돼 스캔 못 하면 채번만 된 빈 FG → 재발행.
- 제품 수량 = **1 고정** (라벨 1장 = 제품 1개). 기존 `qty` 입력 제거.

### 2.4 차감 규칙
- **자재**: BOM 소요량만큼 설비 WIP 자재(`WIP_MAT_STOCKS`)에서 차감(FIFO matUid). `MAT_ISSUE`/수불 기록.
- **반제품**: 스캔된 SG에서 각 1개씩 소비(BOM 수량 강제 아님, 스캔분 = 투입).
- **오투입 방지**: 스캔한 반제품/자재 품목이 이 제품 BOM에 없으면 거부. 수량 초과는 막지 않음.

## 3. 화면 레이아웃 (고정 스캔 영역, 작게)

세로 스택 폐기. 상단 고정 + 2열 작업 영역.

```
┌─────────────────────────────────────────────────────────────┐
│ [작업지시(완제품) 선택 바 — 한 줄, 컴팩트]   [설비 선택]  [초기화] │  ← 상단 고정
├──────────────────────────────┬──────────────────────────────┤
│ ◆ 설비 자재 장착 (지속)         │ ◆ 반제품 스캔 (세트·리셋)        │
│ [자재 스캔 입력 ▮] (고정,작게)   │ [반제품 스캔 입력 ▮] (고정,작게)  │
│ ─ 장착 자재 목록 ──────────     │ ─ 스캔 반제품 목록 ──────────    │
│  품목 LOT 잔량  [해제]          │  품목 SG바코드  [제거]           │
│  ...(스크롤)                   │  ...(스크롤)                    │
│  잔량0 → "보충 스캔" 경고        │  BOM 충족 체크(오투입만)         │
├──────────────────────────────┴──────────────────────────────┤
│ [조립 실행 → FG 라벨 발행]   |   [실물 라벨 스캔 ▮ → 추적성 확정]  │  ← 하단 액션 바(고정)
└─────────────────────────────────────────────────────────────┘
```
- 스캔 입력창은 각 영역 상단에 **고정**, 높이 작게. 목록만 내부 스크롤(`min-h-0`).
- 하단 액션 바: ② 조립 실행(라벨 발행) → ③ 라벨 스캔 입력(발행 후 활성). 두 동작이 한눈에.
- 전체 `h-full flex flex-col overflow-hidden` — 페이지 자체는 스크롤 없이 영역별 내부 스크롤.

## 4. 백엔드 설계

### 4.1 설비 자재 장착 (① WIP_MAT_STOCKS 단일 출처)
- **장착 스캔**: `POST /production/equip-material/mount` — { equipCode, matUid } → MAT_LOTS 확인 + WIP_MAT_STOCKS 적재(QTY/AVAILABLE_QTY) + 수불(WIP_MOVE). 자재 LOT 잔량을 설비 WIP로 이동.
- **장착 목록 조회**: `GET /production/equip-material/mounted?equipCode=` → 설비에 장착된 자재 LOT + 잔량(복원용).
- **명시적 해제(반품)**: `POST /production/equip-material/unmount` — { equipCode, matUid } → WIP_MAT_STOCKS 차감 + 원자재 재고 복원(역 WIP_MOVE).
- 기존 `WipMatStockService`(설비 WIP 차감 FIFO 로직 보유) 재사용/확장.

### 4.2 조립 실행 (② FG 채번 + 라벨)
- `POST /production/assembly/issue-label` — { orderNo, equipCode } → FG 바코드 1개 채번, FG_LABELS status='ISSUED'(라벨 미확정), 라벨 출력 페이로드 반환. **SG·자재·실적·재고 미반영.**

### 4.3 라벨 스캔 확정 (③ 추적성)
- `POST /production/assembly/confirm` — { fgBarcode, orderNo, equipCode, sgBarcodes[] } → 단일 트랜잭션:
  1. FG_LABELS status → 'LABEL_VERIFIED'(또는 매핑 확정 플래그)
  2. genealogy FG→SG (스캔 SG), FG→MAT_LOT (BOM 자재 차감분)
  3. SG 잔량 1씩 소비
  4. 설비 WIP 자재 BOM 소요량 차감(FIFO) + MAT_ISSUE
  5. ProdResult 생성
  6. FG WIP 재고 적재
- 기존 `SubprocessKittingService.kit()` 로직을 ②/③ 2단계로 분리·재구성(자재 차감 추가).

### 4.4 오투입 검증
- 반제품/자재 스캔 시 BOM(`/master/boms/parent/{itemCode}`) 품목 대조. BOM에 없으면 거부. (기존 `JobMaterialLotService.scanAndRegister`의 오장착 검증 패턴 참고)

## 5. 프론트 구조
- `input-assembly/page.tsx` 전면 재작성: 상단 작업지시·설비 바 + 2열(자재장착/반제품) + 하단 액션 바.
- 컴포넌트 분리: `EquipMaterialMountPanel`(자재 장착·해제·복원), `SgScanPanel`(반제품 세트), `AssemblyActionBar`(라벨 발행 + 라벨 스캔 확정).
- 자재 장착 목록은 설비 선택 시 `GET mounted`로 복원. 반제품은 라벨 확정 후 리셋.

## 6. 엣지 케이스
- 라벨 발행 후 스캔 전 이탈 → 빈 FG(ISSUED) 잔존 → 재발행/정리 대상으로 표시.
- 설비 WIP 자재 잔량 < BOM 소요량 → 확정 거부 + "자재 보충 스캔" 안내.
- 동일 SG 중복 스캔/잔량 0/상태 부적합 → 기존 검증 재사용.
- 라벨 스캔 시 BOM 자재가 설비에 미장착 → 거부 + 장착 안내.

## 7. 비범위 (이번 단계 제외)
- 키오스크(input-kiosk) 자재 모델을 설비 단위로 전환 — 별도 후속 단계(조립에서 새 모델 검증 후).
- 설비 자재 장착의 다작업자 동시성/교대 인수인계 UI 고도화.

## 8. 검증 기준
- 자재를 설비에 장착 → 화면 재진입 시 복원, 명시 해제 전 유지.
- 반제품·자재 스캔(준비) 상태에서 SG 잔량/자재 재고 불변.
- 조립 실행 → FG 라벨 1장, 이 시점 매핑·소비·실적 없음.
- 실물 라벨 스캔 → genealogy(FG→SG, FG→MAT_LOT) + SG·자재 차감 + 실적 + 재고가 단일 트랜잭션으로 확정. 추적성 화면(`/quality/trace`)에서 그 FG로 조회 시 반제품·자재가 매핑되어 표시.
- BOM 외 품목 스캔 거부. 제품 수량 1.
- `pnpm --filter @harness/backend exec tsc --noEmit` / `--filter @harness/frontend` 0건.
