# 작업지시는 번호 단독, 실적은 공정별, 공정은 설비 선택으로 결정한다

## Context

작업지시 1건이 라우팅의 여러 공정을 거치고, 생산실적은 공정별로 기록된다. 그런데 현재 화면마다 "현재 공정"을 정하는 방식이 달랐다: 키오스크는 작업지시의 `processCode`(최초공정) 고정, 서브공정·조립은 설비 선택으로 공정 도출. 또한 작업지시 PK를 공정별로 쪼개자는 안도 검토됐다.

## Decision

- **작업지시 PK = 작업지시번호 단독**. 공정별로 분할하지 않는다. 여러 공정이 같은 작업지시를 공유하고, 각 공정이 자기 실적만 입력한다.
- 작업지시는 **라우팅이 필수**다(공정별 발행·차감·라벨이 전부 라우팅에 걸리므로, 라우팅 없는 작업지시는 모델이 성립하지 않는다).
- **공정은 설비 선택으로 결정**한다. 설비 1개 = 공정 1개. 실적 입력 시 선택한 설비의 공정이 작업지시 라우팅에 있는지 검증하고, 없으면 **오류**(예외 배제 원칙).
- 떼어낼 수 없는 복합 작업(1설비가 여러 작업을 한꺼번에)은 라우팅에서 **1개 통합 공정**으로 정의해 설비-공정 1:1을 유지한다.
- 키오스크·서브공정·조립 **3화면의 공정 결정 방식을 (설비→공정) 으로 통일**한다.

## Considered options

- **작업지시 PK를 작업지시번호+공정으로 분할** → 이미 PARENT_ID/ROOT_ORDER_NO가 BOM 계층 분할에 PK를 쓰고 있어 공정 분할까지 넣으면 두 축이 엉킴. "공정별 식별"은 ProdResult.processCode로 이미 충족돼 분할 불필요. 기각.
- **공정을 작업자가 직접 선택** → 설비가 곧 공정이라 입력 1번으로 충분. 현장 직관에도 설비 선택이 자연스러움. 기각.
- **복합 설비를 설비-공정 1:N 매핑 + 실적 자동 전개** → 3공정이 떼어낼 수 없는 한 덩어리라 통합 공정 1개로 두는 게 단순하고 충분. 기각.
