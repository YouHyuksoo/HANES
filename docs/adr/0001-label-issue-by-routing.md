# 라벨 발행 종류를 라우팅 공정 설정으로 제어하고, 묶음/회로를 한 테이블에서 LABEL_TYPE으로 구분한다

## Context

와이어하네스 생산은 **묶음**(원자재 절단 가닥 묶음) → **회로 반제품(SG)** → **완제품(FG)** 3단계로 라벨이 발행된다. 묶음과 SG는 도메인상 별개지만 "라벨 + 가닥 수 재고 + 설비 장착 + 공정 추적"이라는 구조가 동일하다. 또한 제품마다 공정 구성이 가변적이다. 현재 코드는 묶음과 SG를 `SG_LABELS` 한 테이블에 구분 없이 뭉쳐 발행한다.

## Decision

- 묶음과 회로(SG)는 별도 테이블로 나누지 않고, `SG_LABELS`에 **`LABEL_TYPE`(묶음 / 회로)** 컬럼으로 구분한다. (재고·추적 로직을 한 벌로 공유)
- 라벨 발행 종류는 공정 위치 자동판정이 아니라, 라우팅 공정의 단일 컬럼 **`ISSUE_LABEL_TYPE`(없음/묶음/SG/FG)** 으로 정한다. **한 공정은 한 종류만** 발행한다.
- 기존 `ROUTING_PROCESSES.ISSUE_SG_LABEL_YN` / `ISSUE_FG_LABEL_YN`(Y/N 2개)는 `ISSUE_LABEL_TYPE` 단일 컬럼으로 통합한다(Y였던 공정을 SG/FG로 이관).

## Considered options

- **묶음을 별도 테이블(BUNDLE_LABELS)로 분리** → 동일한 재고·추적 로직을 두 벌로 만들어야 해 기각.
- **발행 종류를 최초공정 여부로 자동판정** → 제품별 공정 구성이 가변이라 깨짐. 라우팅 설정이 유연.
- **Y/N 다중 플래그 유지** → "묶음=Y, SG=Y" 모순 조합 가능. 한 공정 한 종류라 단일 컬럼이 명확.
