# HANES MES 고객 소개 자료 작업지시서

## 목적

HANES MES를 고객에게 소개하기 위한 가로형 제품 소개 자료를 만든다. 설명서가 아니라  시스템 기능  소개 자료이므로 화면 중심으로 구성하고, 하네스 제조 업종에서 중요한 추적성, 검사 품질, 불량 원인 추적, 출하 이력 관점을 부각한다.


## 주요 내용 


1. 자재관리
    ㅇ 자재 입고 프로세스 
        ✱ 발주정보 입력 (ERP 인터페이스) 
        ↓
        ✱ 자재 입하 - 자재시리얼 생성 및 바코드 라벨 발행 
        ↓         
        ✱ IQC검사 및 판정 (미 대상품도 필요시 검사 가능)
        ↓         
        ✱ 자재입고
             * IQC 합격시 : 자재창고로 이동 (자재창고가 여러개 있을시 지정가능)
             * IQC 불합격시
                  1) 특채대상 시리얼 지정시 : 특채대상은 자재창고로 이동 (특채정보 관리됨)
                  2) 특채대상 시리얼 미지정 : 모두 반품대기창고로 이동처리
             * 입고 시 발행된 시리얼바코드라벨과 제조사바코드라벨을 교차로 스캔하여 정보 매핑 (PC, PDA 공통)
        ↓
        ✱ 파괴검사 샘플 기타출고 처리 (자동)


    ㅇ 자재 불출 프로세스
        ✱ 작업지시 발행 
        ↓
        ✱ 작업지시 기반 불출요청서 생성 (자동)
        ↓
        ✱ 자재목록에 있는 자재 시리얼 스캔 후 현장 불출 (PC, PDA 공통)
           * 자재 불출요청서에 없는 자재도 불출은 가능하나 작업 지시번호 매칭이 안되고, 이력에서 구분 가능


    ㅇ 자재 폐기 프로세스 - 자재창고
        ✱ 불량(불용) 판정 등록
        ↓
        ✱ 폐기대기 창고 이동
        ↓
        ✱ 자재폐기 처리


    ㅇ 자재 폐기 프로세스 - 생산불출자재
        ✱ 자재창고로 자재 반납
        ↓
        ✱ 불량(불용) 판정 등록
        ↓
        ✱ 폐기대기 창고 이동
        ↓
        ✱ 자재폐기 처리


    ㅇ 장기보관 및 자재수명 관리
         • 품목정보(기준정보)에 유효기간(일), 유효기간 연장(일) 지정
             * 유효기간이 지난 자재는 사용불가
             * 입고일 기준 최초 유효기간 만료일 : 입고일 + 유효기간(일)
             * 최초 재검사에서 합격 판정시 유효기간 만료일 : 검사일 + 유효기간 연장(일)
             * 유효기간 만료 도래 10일전 부터 자재유수명관리 프로그램에서 리스트 업
             * 유효기간 만료 도래시 유수명자재 재검사를 통해 합격시 유효기간 연장 (유효기간 도래 10일전 부터 검사 가능하며, 만료시에도 검사 가능)
             * 유효기간 연장(일)은 최대 연장 기간, 상황(우기, 혹서기 등)에 따라 유효기간 연장(일) 보다 적게 연장 가능, 초과는 불가
             * 연장된 유효기간 재 도래시 동일한 방법으로 유효기간 재 연장 가능
             * 설정 예 
                  - 테잎 : 유효기간 180일 / 유효기간 연장(일) 60일
                  - 케이블 : 유효기간 360일 / 유효기간 연장(일) 180일
 
        ✱ 자재입고 : 테잎
        ↓
        ✱ 유효기간 도래 (180일 경과, 170일일 경과 시부 부터 재검 가능, 자재유수명관리 화면에서 대상 확인 가능)
        ↓
        ✱ 유수명자재재검사 프로그램에서 검사 결과 입력 (자재 IQC 검사와 동일한 형태로 진행)
        ↓
        ✱ 합격 시 품목정보(기준정보)에서 설정한 유효기간 연장(일) 이내 유효기간 연장
            * 불합격시 불용자재로 전환
        ↓
        ✱ 연장된 유효기간 만료 도래시 재검사 (반복)

    ㅇ 자재시리얼 분할/병합
         • 자재시리얼 분할 시 모(母) 시리얼 번호 정보를 관리하여 추적성 확보 
         • 자재시리얼 병합은 분할된 자재 시리얼을 병합하는 의미로 최초의 시리얼이 다른 자재끼리는 병합불가



2. 생산실적 / 공정검사 관리
    ㅇ 작업지시 생성
         • 작업지시는 모델단위로 생성시 하위 반제품 작업지시 자동 생성 및 연계
         • 필요에 따라 반제품 단위로 생성도 가능
         • 공정에 맞는 설비 수동 지정

    ㅇ 공정검사 관리 설정 (샘플검사)
         • 초/중/종물 검사 판정에 대한 조건은 라우팅 정보에서 생산품목의 공정별로 구성가능 
           수치를 확인하여 입력하는 측정형 (LSL, USL 관리)과 육안 및 기능 조작등 으로 확인하는 판정형으로 검사항목 분류
         • 생산 설비에서 위치에서 바로 확인이 가능한 직접검사항목 (탈피길이, 외형 등)은 생산실적입력 프로그램 내 팝업 프로그램에서 직접 입력 가능
         • 별도의 측정설비가 필요한 경우 검사의뢰를 통해 측정설비에 있는 PC에서 의뢰검사입력 프로그램을 통해 측정값 입력 가능 (인장력 검사 등)
         • 검사결과 양품 조건 미 충족시 문제확인 및 조치 후 다시 입력, 양품으로 판정 되어야 다음 프로세스 진행 가능
         • 파괴검사시 샘플 제작 시료만큼 자재 출고처리


    ㅇ 작업 및 실적입력 프로세스
        ✱ 작업지시 발행 (생산팀)
        ↓
        ✱ 자재불출요청서 발행
        ↓
        ✱ 자재불출요청서 확인 및 자재 불출 (자재팀)
        ↓
        ✱ 진행공정 설비에 있는 PC에서 작업지시번호 스캔
        ↓
        ✱ 작업자 정보입력
        ↓
        ✱ 사용자설비점검 내용 입력
        ↓
        ✱ 작업지시 품목의 BOM을 확인하여 자재목록 표시
        ↓
        ✱ 사용자재 시리얼 바코드를 스캔 및 마운트 처리를 하여 자재오입 방지
        ↓
        ✱ 설비소모품 바코드를 스캔 및 마운트 처리를 하여, 치공구선택 착오 방지
        ↓
        ✱ 생산작업 시작
        ↓
        ✱ 공정검사 (샘플검사)
              * 작업지시상 첫 작업일 경우 초물검사 수행 (패스를 하여야 생산 실적 입력 가능, 인터락)
              * 중물검사는 여러번 입력 가능, 작업지시상 생산지시수량의 70%가 진행될때 까지 중물검사 입력이력이 없으면 중물검사 내용 입력시 까지 인터락
              * 작업지시상 생산지시수량의 40%가 진행될때 까지 중물검사 입력 이력이 없으면 작업실적 입력 화면에 리마인드 메세지 출력
              * 종물검사는 작업지시상 마지막 작업수량 입력 전에 입력 
        ↓
        ✱ 생산 결과 입력 
              * 마운트된 자재 사용량 만큼 자재 차감
              * 생산수량 만큼 설비소모품 사용횟수 증가
              * 불량품은 불용처리 되어 불량창고로 이동


3. 설비관리
    ㅇ 설비마스터        
        • 설비 코드 및 설비명, 설비유형, 제조사, 모델 정보관리
          설비 통신 방식으로는 MQTT, TCP/IP, Serial, OPC-UA, Modbus 가 준비되어 있음
          설비 도입시 통신연결을 위한 추가 작업 필요

    ㅇ 공정관리
        • 공정정보 및 공정유형 관리, 공정별 해당되는 설비 지정 

    ㅇ 설비소모품관리 (커터날, 어플리케이터 등)
         • 설비소모품은 소모품 재고로 관리하며, BOM에 포함시키며
           작업준비시 BOM 데이터를 근거로 설비 소모품이 제대로 사용 되었는지 확인
           작업 실적 입력시 사용횟수만큼 차감하며, 사용가능 횟수 관리

    ㅇ설비일일점검 (설비일상점검) - 설비관리 담당자 수행
        • 설비점검항목마스터에서 설비 유형별 검사항목 관리
          설비별 점검항목에서 각 설비별로 유형에 따라 설비점검항목 마스터에서 등록된 검사항목 등록
          측정값을 입력하는 측정형 검사 (LSL, USL 관리)와 상태를 육안으로 확인하여 판정하는 판정형 검사로 분류
          일일설비점검 미수행시 해당 설비는 사용 불가
          일일설비점검시 문제가 생기면 조치 후 다시 실적 입력
          점검기준시간 설정 가능 (기본 오전 8시)

    ㅇ설비일일점검 (설비일상점검) - 생산 작업자 수행
        • 설비점검항목마스터에서 설비 유형별 검사항목 관리
          설비별 점검항목에서 각 설비별로 유형에 따라 설비점검항목 마스터에서 등록된 검사항목 등록
          검사항목별로 ID를 할당하고 ID 정보가 담긴 QR코드 발행 및 부착, 생산작업 시작시 QR코드 스캔 후 판정
          문제 없을시 생산 작업시작, 작업지시가 변경 될때 마다 수행



4. 제품 포장 및 출하관리
    ㅇ프로세스       
        ✱ 포장용 바코드 생성 및 라벨 발행, 부착
        ↓
        ✱ 포장용 바코드를 스캔하여 포장 진행 (PC, PDA)
        ↓
        ✱ 영업팀 인계 (영업창고로 이동)
        ↓
        ✱ 출하지시 발행
        ↓
        ✱ 출하지시 바코드 스캔
        ↓
        ✱ 포장박스 바코드 스캔
        ↓
        ✱ 바코드 스캔한 박스 출고처리

    ㅇ상세내용       
        • 포장용 바코드 발행시 품목정보 포함, 품목관리(기준정보)에서 박스입수량 확인
          박스입수량은 한 박스내 최대 포장 수량으로 박스입수량 보다 적게 포장 가능
        • 출하지시에는 고객사 정보, 품목 및 수량 정보, 고객사 SCM 관련정보 등이 포함
        • 포장된 박스도 해체 후 재포장 가능


## 핵심 요구

- 문서는 가로형으로 만든다.
- 장수 제한을 두지 않는다. 화면 흐름과 전달력이 우선이다.
- 글자는 크게 쓰지 말고 화면을 침범하지 않게 한다.
- 한 장에 기준정보 화면 여러 개를 묶어 보여줘도 된다.
- 아이콘은 많이 쓰지 않는다. 화면 캡처와 짧은 문구를 중심으로 한다.
- 문서 작성 방법을 설명하지 말고, 실제 제품 소개 자료를 만든다.
- 현재 메뉴에 있는 화면을 최대한 캡처해서 넣는다.
- 빈 대시보드 느낌보다 실제 메뉴, 실제 업무 흐름, 실제 화면 증거를 우선한다.

## 자료 구성 원칙

1. 첫 화면은 HANES MES가 무엇을 해결하는지 바로 보여준다.
2. 기준정보는 여러 화면을 묶어 "운영 기준을 먼저 표준화한다"는 메시지로 구성한다.
3. 자재는 입하, LOT, 재고, 수불 이력 흐름으로 구성한다.
4. 생산은 현장 키오스크, 작업 진행, LOT 소비/생산 연결을 강조한다.
5. 검사는 검사 결과, 불량 등록, 재검사, 판정 이력을 강조한다.
6. 출하는 박스, 개별 제품, 출하 이력, 역추적 관점으로 구성한다.
7. 마지막은 "제품 -> 공정 -> 검사 -> 자재 LOT" 역추적 메시지로 닫는다.

## 권장 슬라이드 흐름

1. 표지: 하네스 제조 MES를 현재 화면으로 소개
2. 현재 메뉴 커버리지 맵
3. 기준정보 묶음 1: 품목, BOM, 거래처, 설비
4. 기준정보 묶음 2: 공정, 라인, 라우팅, 작업달력, 작업자, 라벨
5. 자재/재고 묶음: 자재 재고, 수불, 실사
6. 자재 입하/LOT: 바코드와 자재 LOT 연결
7. 생산/현장 키오스크: 작업자가 스캔으로 실적 처리
8. 검사/품질: 검사 결과와 판정 이력
9. 불량 조치/재검사: 불량 등록, 조치, 재검증
10. 출하/박스: 박스와 개별 제품 단위 추적
11. 역추적: 제품에서 자재 LOT까지 연결
12. 기준정보 화면 갤러리
13. 자재/재고 화면 갤러리
14. 구현 범위와 고객 가치 요약
15. 시연 흐름 마무리

슬라이드는 15장에 고정하지 않아도 된다. 메뉴 캡처가 더 확보되면 기준정보, 자재, 생산, 검사, 품질, 출하 영역별로 추가한다.

## 캡처 우선순위

1. 실제 고객에게 보여줄 메뉴 화면
2. 기준정보 화면: 품목, BOM, 거래처, 설비, 공정, 라인, 라우팅, 작업달력, 작업자, 창고, 라벨
3. 자재/재고 화면: 자재 입하, 자재 재고, 수불 이력, 실사
4. 생산 화면: 투입, 키오스크, 작업지시, 실적
5. 검사 화면: 검사 결과, 검사 항목, 판정, 재검사
6. 품질 화면: 불량 등록, 불량 조치, 개선 요청
7. 출하 화면: 박스, 출하, 개별 제품 조회

캡처가 빈 데이터로 보이더라도 현재 메뉴 구조와 화면 형태를 보여주는 용도라면 사용할 수 있다. 단, 고객 가치 설명에는 실제 업무 캡처나 안정 캡처를 우선 배치한다.

## 로컬 실행 기준

프로젝트 상황에 따라 포트가 달라질 수 있으나, 기존 작업 기준은 다음과 같다.

- Frontend: `http://localhost:3002`
- Backend: `http://localhost:3003`

캡처 자동화 시 로그인 또는 API 응답 문제로 화면이 막히면 다음 방식으로 처리한다.

- `/api/health`, `/api/db-info`는 정상 응답이 필요하다.
- 화면 형태 캡처가 목적이면 데이터 API는 빈 배열 또는 빈 객체로 대체할 수 있다.
- `ConnectionCheckOverlay`가 캡처를 막으면 health/db-info 응답을 먼저 안정화한다.
- 캡처 결과가 너무 작은 파일이면 빈 화면일 가능성이 높으므로 발표 자료에는 넣지 않는다.

## 문구 작성 기준

한 슬라이드에는 짧은 제목, 한 줄 설명, 2-4개의 짧은 포인트만 둔다.

좋은 문구 예:

- 자재 LOT부터 완제품 출하까지 이력을 연결합니다.
- 검사 결과와 불량 조치가 같은 흐름 안에 남습니다.
- 기준정보가 표준화되어 라인별 작업과 품질 기준이 흔들리지 않습니다.
- 문제가 발생하면 제품, 공정, 검사, 자재 LOT 순서로 빠르게 역추적합니다.

피해야 할 문구:

- 기능을 길게 설명하는 매뉴얼형 문장
- 구현 방법 중심 설명
- 고객이 보지 않아도 되는 내부 개발 절차
- 화면보다 큰 제목과 긴 본문

## 디자인 기준

- 비율: 16:9 가로형
- 배경: 흰색 또는 짙은 남색 계열을 섞되 한 가지 색만 과하게 쓰지 않는다.
- 화면 캡처는 가능한 크게 배치한다.
- 여러 화면을 묶을 때는 2x2, 3x2 그리드를 사용한다.
- 캡션은 짧게 쓴다.
- 아이콘은 보조 용도로만 쓴다.
- 버튼이나 UI처럼 보이는 장식 요소는 최소화한다.
- 텍스트가 캡처 위를 가리지 않게 한다.

## 검증 기준

완료 전에 최소한 아래를 확인한다.

- PPTX가 열리는지 확인
- HTML이 브라우저에서 열리는지 확인
- 슬라이드 수가 의도한 구성과 맞는지 확인
- 이미지 누락이 없는지 확인
- 텍스트가 박스 밖으로 침범하지 않는지 확인
- 캡처가 너무 흐리거나 빈 화면처럼 보이지 않는지 확인
- 고객에게 보여주는 관점이 기능 목록이 아니라 업무 가치 중심인지 확인


## 주의

- 사용자에게 "문서 만드는 법"을 설명하지 않는다.
- 사용자가 원하는 것은 실제 산출물이다.
- 현재 메뉴 캡처를 최대한 넣되, 품질이 낮은 캡처는 갤러리나 부록 수준으로만 사용한다.
- 이전 AI나 사용자가 만든 변경사항을 되돌리지 않는다.
- 커밋은 사용자가 요청할 때만 한다.
