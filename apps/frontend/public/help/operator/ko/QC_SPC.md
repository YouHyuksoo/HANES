# 고전압 하네스 SPC 관리도 — 운영 가이드

## 시스템 목적·역할
공정 검사 측정값을 서브그룹(n=5)으로 묶어 X̄-R 관리도, 공정능력(Cp/Cpk/Pp/Ppk), Western Electric 규칙 위반을 산출해 보여주는 **조회 전용** 화면입니다. 관리한계·능력지수·규칙 판정은 전부 백엔드가 계산하고, 화면은 값을 읽어 색만 입힙니다. 운영자는 데이터 소스(목업/실 DB) 상태와 관리대상·규격 정의가 현장 도면 기준과 맞는지 확인합니다.

## 데이터 구조
```
GET /quality/spc/hv/targets?days=&k=            관리대상 요약 (sourceKind, dateFrom, dateTo, targets[])
GET /quality/spc/hv/targets/:targetId?days=&k=  서브그룹·관리한계·능력지수·규칙 위반
sourceKind: MOCK (예시 생성) | ORACLE (검사이력 연동)
스코프: COMPANY='40', PLANT_CD='1000'
```

## 사전 설정 (마스터·공통코드)
- 관리대상(공정 코드·품목·특성·규격 LSL/T/USL·소수 자릿수·설비 후보)은 백엔드 `quality/spc/hv` 모듈 카탈로그로 관리합니다. 공정 코드는 PROCESS_MASTERS 코드를 따릅니다.
- 규격값은 도면 규격으로 유지해야 Cpk 가 의미를 가집니다. 단측 규격은 없는 쪽을 null 로 둡니다.
- 데이터 소스 전환(MOCK ↔ ORACLE)은 백엔드 설정으로 합니다. 화면은 응답의 `sourceKind` 만 보고 배너를 켜고 끕니다.

## 버튼·API·상태 전이
| 조작 | API | 설명 |
|------|------|------|
| 기간 7/14/30/60일 | `days` 파라미터 | 오늘 포함 최근 N일. 관리한계·능력지수가 구간 기준으로 재계산 |
| 서브그룹 전체/25/50 | `k` 파라미터 (0=전체) | 최근 k 서브그룹만 사용. 서브그룹 id 는 1..k 로 재부여 |
| 공정 선택·검색 | 없음 (클라이언트 필터) | 목록 응답을 화면에서 걸러냄 |
| 목록 행 클릭 | 상세 API 호출 | 60초 자동 재조회, 이전 데이터를 유지한 채 갱신 |

상태(health) 판정 — 서버 단일 기준, 최근 25개 서브그룹만 평가:
```
R1/RR1 위반 있음          → OOC   (이탈, 적색)
R2~R4 위반 또는 Cpk<1.33  → WARN  (주의, 황색)
그 외                     → STABLE(관리상태, 초록)
```
능력지수 숫자 색: ≥1.33 정상, ≥1.00 주의, 미만 부적합, null 회색(`미산출`).

## 운영 절차
1. 툴바 우측 배너로 데이터 소스를 확인합니다. "목업 데이터" 배너가 있으면 실 검사이력이 아닙니다.
2. 이탈·주의 건수 요약을 보고, 좌측 목록에서 적색 상태 점 특성부터 확인합니다.
3. 우측 규칙 위반 목록의 서브그룹 번호·시각·설비·LOT 로 현장 원인을 추적합니다.
4. 규격이 도면과 다르거나 관리대상이 빠졌으면 백엔드 카탈로그 정정 후 재조회합니다.
5. 실 DB 전환 후에는 서브그룹 묶음(일자별 5개, 나머지 버림) 규칙이 검사 방식과 맞는지 검증합니다.

## 권한
- 일반 사용자·운영자 모두 조회만 가능합니다. 화면에서 데이터를 등록·수정·삭제하지 않습니다.
- 관리대상·규격·데이터 소스 변경은 개발/운영 관리자 작업입니다.

## 문제 해결 (트러블슈팅)
| 증상 | 원인 | 조치 |
|------|------|------|
| 목록이 비어 있음 | 조회 기간 안 서브그룹 없음, 공정 필터/검색 조건, 백엔드 미기동 | 기간을 늘리고 필터를 초기화. 백엔드 `/quality/spc/hv/targets` 응답 확인 |
| 상세가 "불러오는 중"에서 멈춤 | 상세 API 404/500 | targetId 가 카탈로그에 있는지, 서버 로그 확인 |
| Cp 가 미산출 | 단측 규격 | 정상. 양측 규격이 있어야 Cp 산출 |
| 관리도 미표시 ("서브그룹 2건 미만") | 데이터 부족 | 기간 확대 또는 검사 데이터 적재 확인 |
| 상태 점과 관리도 이상점이 불일치 | 상태는 최근 25개만 평가 | 설계 의도. 오래된 이상점은 관리도에만 표시 |
| 배너가 계속 "목업 데이터" | 백엔드 소스 설정이 MOCK | 백엔드 데이터 소스 설정을 ORACLE 로 전환 |
